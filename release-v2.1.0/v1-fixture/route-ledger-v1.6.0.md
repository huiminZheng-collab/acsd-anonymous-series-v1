# ACSD v1.6.0 路线审计账本

日期：2026-09-09。状态词只使用 `attempted`、`unexplored`、`ruled out`；`ruled out` 仅指在本版明确目标和威胁模型下有反例或结构性矛盾，不表示普遍不可能。

## 最小研究对象

两篇匿名论文 P、Q 在首次发布时互相引用；每篇可脱离系列独立验证；随后存在修订、合法分支、相同槽位冲突、系列密钥轮换，以及复制正文后以另一套键重签的对照谱系。

## 证据分类

- 构造证据：确定性语料包含单篇、互引、修订、分支、冲突、轮换和复制谱系。
- 独立复验：Python 生成/参考路径与零依赖 Node 严格 CBOR/COSE 验证路径一致。
- 反例证据：合法分支反驳“多孩子即作恶”；复制重签反驳“有效签名即原创”；本地观察反驳“有时间字段即独立时间”；签名正确但秩不足的包反驳“验签成功即具有无环承诺资格”；签名正确但未获正文支持的语义边、正文/引用清单不一致、字节见证偏移错误或 JSON 非规范的 release，反驳“系列签名者、清单字段或宽松解析器可任意解释论文关系”。
- 来源证据：W3C PROV、SWHID、Trusty URIs、RFC 9052、RFC 9943 分别登记来源类型和已覆盖能力。
- 尚缺证据：真实外部时间、透明日志组合、真人身份解析、跨论文选择性链接和用户隐私评估。

## 失败预演

假设这个方向最终失败，最可能的原因如下：

1. **新颖性不足。** 预警：评审认为只是 PROV + 内容寻址 + COSE。缓解：把论文主张收缩到形式化安全目标、匿名学术专属冲突语义、可执行反例和组合边界，并与最接近方案逐项对照。
2. **WorkID 被抢注或碰瓷。** 预警：不同谱系都声称同一可读标识。缓解：使用高熵随机 ID；任何“控制 WorkID”的含义必须来自已签包和外部先后证据，而非字符串占有。
3. **系列键成为中心化单点。** 预警：系列维护者能隐瞒合法分支或制造双视图。缓解：接入此前的 witness quorum、cross-logging 和 gossip 组件；系列签名只授权声明，不宣告内容真相。
4. **关系图泄露匿名团队。** 预警：互引时间和作者槽位模式可重新识别团队。缓解：最小公开投影、分期披露、关系承诺或加密边，并做可量化的链接性评估。
5. **用户把“较早承诺”当成“原创判决”。** 预警：UI 使用“作者已证明/抄袭已证明”。缓解：协议和界面坚持 `VALID`、`EQUIVOCATION`、`INDETERMINATE` 的证据型措辞，原创/授权争议进入单独裁决流程。

## 下一最小实验

把 v1.6.0 的 `bundle-epoch0-seq1.scitt` 同时送入既有 RFC 3161 适配器与至少一个透明服务收据路径，再构造“复制谱系先在某一服务出现、原谱系在另一服务更早出现”的分区反例。目标不是自动裁定抄袭，而是明确哪些门限观察条件足以支持全局先后结论。
