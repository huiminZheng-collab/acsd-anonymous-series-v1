# ACSD Anonymous Scholarly Series DAG — v1.6.0

这是“可认领的匿名学术披露”研究线的系列论文原型。它回答两个问题：单篇论文是否被迫依赖系列，以及多篇匿名论文前后引用、互相引用、修订和分支时怎样形成可验证谱系。

答案是：单篇不依赖系列。系列是严格可选的第二层；互引使用稳定 `WorkID`，待各单篇完成后再由签名系列包映射到精确 `ReleaseID`，从而允许语义有环而密码依赖无环。

## 一键离线复现

在 PowerShell 中运行：

```powershell
.\run.ps1
```

脚本不联网：它从 `vendor/` 的锁定归档加载 Python 依赖，重新生成确定性测试夹具，以零依赖 Node.js 验证器交叉复验，最后生成并检查公开文件清单。

预期核心结果：

- 8/8 单篇版本无需系列即可验真；
- 18/18 作者背书绑定正确版本；
- 4 个系列包和 1 个轮换声明有效；
- 每份 release 的 `reference_work_ids` 都等于精确正文中出现的规范 `urn:uuid:…` WorkID 令牌，且每个令牌都有签名的 `(work_id, byte_offset, byte_length)` 字节见证；
- 另有 5 个签名正确、但分别秩过低、伪造论文语义边、正文/引用清单不一致、引用见证偏移错误、或 release JSON 非规范的负夹具被拒；
- 13/13 场景命中封闭预期判定；
- 11 个固定规范 JSON 语料在 Python 与 Node.js 中逐例同判，覆盖重复键、非 ASCII 键、浮点数、越界整数、空白与损坏 JSON；
- 所有由 profile 指向的工件路径均被约束在项目根目录内，父目录逃逸会被拒绝；
- 语义互引图有环，密码依赖图无环；
- 复制重签、自然人身份、独立时间和法律不可抵赖性均不被过度声称。

`private-test-keys/` 只含确定性演示私钥，被公开清单排除，绝不可用于生产。真实部署还必须接入硬件或受控密钥、RFC 3161/透明日志、撤销与恢复政策。

这里的正文解析刻意很窄：只识别字节中明确写出的规范 WorkID 令牌，并不声称从自然语言、PDF
排版或参考文献格式推断“真正的学术引用”。`citation_witnesses` 固定每个令牌的 UTF-8
字节区间，`reference_work_ids` 则是这些见证的去重有序投影；两者都由 release 签名承诺。
这给引用字段可复验的字节绑定，但不把语义理解问题伪装成已解决。

每个被签名的 release、系列包、轮换和观察对象还必须是本剖面唯一的规范 JSON 字节串：递归排序
ASCII 对象键、无空白、仅安全整数。验签成功但在 JSON 前多一个空格也会被拒绝；这防止重复字段、
非规范数字或解析差异让同一签名在不同实现中产生不同字段解释。本规则是本原型的窄剖面，不应误称为通用 JSON 标准。

## 主要入口

- `architecture.md`：双层对象、冲突谓词和安全边界；
- `route-ledger-v1.6.0.md`：路线审计和失败预演；
- `generate.py`：确定性语料生成与 Python 参考判断；
- `verify-independent.cjs`：不依赖生成器逻辑的严格 CBOR/COSE 验证；
- `artifacts/scenarios.json`：11 个正常、攻击和不确定场景；
- `evidence/independent-verification-results.json`：完整机器判定；
- `commitment_anchor_rank`：系列锚点高于所解析版本的结构证书；它不是时间或优先权字段；
- `source-provenance.json`：标准、前人工作与软件哈希边界。

## 研究边界

W3C PROV、SWHID、Trusty URIs、COSE 和 SCITT 已分别覆盖通用溯源、内在标识、可验证引用和签名声明等基础。本版不声称发明这些机制；可检验的增量是匿名学术系列的应用剖面、两阶段互引规则、显式槽位冲突谓词，以及防止把“有效另一谱系”误判为原创性证明的一组反例。
