# ACSD v1.6.0：匿名论文系列的双层对象模型

## 1. 设计结论

单篇论文是完整的基本对象；系列是可选的上层对象。验证单篇论文时，验证者不得下载、信任或知道任何系列包。系列层只表达跨论文关系、系列版本、密钥轮换和冲突证据。

```text
语义层（允许有环）       P --引用--> Q
                         ^           |
                         |-----------|

密码承诺层（必须是 DAG） bundle_2 --> rotation --> bundle_1
                              |                       |
                              v                       v
                         P-v2 / Q-v2            P-v1 / Q-v1
```

互引论文先在正文中引用随机生成、稳定但非内容寻址的 `WorkID`；两篇论文定稿并各自签名后，再由系列包把 `WorkID` 映射到精确的内容寻址 `ReleaseID`。因此语义图可以成环，哈希依赖图仍然无环。

## 2. 单篇层

一份 `PaperRelease` 至少承诺：

- 随机 `work_id`；
- 显式槽位 `(work_id, version, line)`；
- 正文路径、长度和 SHA-256；
- 可选的父 `release_id`；
- 从精确正文提取的有序 `citation_witnesses`：每项为 `(WorkID, UTF-8 byte_offset, byte_length)`，且与正文逐项相等；其去重有序投影为稳定 `reference_work_ids` 列表（本夹具只识别显式 `urn:uuid:…` 令牌）；
- 有顺序的匿名作者槽位、角色、贡献声明；
- AI 使用声明及承担复核责任的人类作者键；
- 声称的签发时间。

其内容标识是规范化 `PaperRelease` 字节的哈希：

```text
ReleaseID = urn:sha256:H(canonical(PaperRelease))
```

每名列名作者分别用自己的匿名 Ed25519 键对同一份规范化字节作 COSE Sign1 背书。独立验真条件仅是：正文哈希、对象哈希、作者公钥、每份背书及字段约束全部匹配。`series_required_for_verification` 固定为 `false`。

本剖面还拒绝“虽被正确签名、却有多种 JSON 写法”的 release 体：签名载荷必须等于递归排序 ASCII
键、无空白、仅安全整数的规范 JSON。此处的目标是消除跨实现字段解释歧义，而不是把这个受限编码冒充为一般 JSON 互操作标准。

这证明的是“这些键共同认可这份精确对象”，不是这些键对应哪些自然人，也不是内容原创。

## 3. 系列层

系列包 `B_k` 承诺：

```text
B_k = Sign_series(
  series_id, epoch, sequence, previous_bundle_sha256,
  rotation_sha256, exclusive_sequence,
  commitment_anchor_rank,
  releases[], heads{}, semantic_edges[]
)
```

其中 `releases[]` 把 `WorkID`、槽位和精确 `ReleaseID` 绑定；`heads{}` 给出各工作的当前头；`semantic_edges[]` 表达互引、补充或其他跨论文关系。系列包只能引用已经完成的论文版本、上一系列包和已经完成的轮换声明，不能反向成为单篇包的依赖。

`commitment_anchor_rank` 是签名对象内的结构证书：它必须严格大于该包每个
`releases[].slot.version`。因此，若把“系列锚点→release”与“较新 release→父 release”
合并，每一步都沿秩下降。它不表示 `issued_at`、RFC 3161 时间、发表先后或创作优先权；
有限包通常可取所含最大版本号加一。

系列密钥轮换由旧 epoch 密钥签名，绑定新公钥哈希、双方 `kid`、生效序号和上一系列包哈希。只拿到 epoch 1 新密钥和新包、却没有旧密钥授权的轮换声明时，新包不被该系列接受。

## 4. 版本、分支和冲突

“同一父版本出现两个孩子”不是冲突的充分条件，因为论文可能合法地分成正文线和计算附录线。

论文级冲突谓词是：

```text
valid(R1) and valid(R2)
and slot(R1) = slot(R2)
and ReleaseID(R1) != ReleaseID(R2)
```

系列级冲突谓词是：两个有效系列包具有相同的
`(series_id, epoch, sequence, previous_bundle_sha256)`，均声明该序号排他，却承诺不同内容。

这样，显式不同 `line` 的平行分支被接受；完全相同排他槽位的双重发布才产生可验证的 equivocation 证据。

## 5. 复制、重签与时间

复制者可以复制正文，用新 `WorkID`、新作者键和新系列键重新签名。这会产生密码学上有效的另一条谱系，而不是无效签名。因此：

- 相同正文哈希 + 不同谱系，只能判为 `INDETERMINATE/CONTENT_REUSE_DIFFERENT_LINEAGE`；
- 若原谱系此前已有独立时间戳或透明日志收据，可以证明某份承诺不晚于某时存在，并支持先后关系；
- 即使证明先后，也不能仅凭密码学自动判定抄袭、授权转载、共同来源或原创性。

本夹具中的观察者和时间均为本地确定性数据，明确标记 `independent_time:false`，不能冒充 RFC 3161、SCITT 登记或其他独立时间证据。

## 6. 隐私与身份边界

P、Q 使用不同的论文级作者别名键。系列包把作品联系起来，但不自动把两个作者槽位联系成同一自然人。若要求“必要时证明 P 的作者 1 就是 Q 的作者 2”，需要另加选择性可链接凭证或零知识证明；v1.6.0 没有实现，因此判为 `AUTHOR_LINK_UNPROVEN`。

公开 `semantic_edges` 还会泄露研究主题关系和大致发布顺序。未来可把公开投影限制为最小关系，或对关系边加密/承诺；这不是本版已经解决的问题。

## 7. 已验证的不变量

1. 删除所有系列包后，8 份单篇版本仍可独立验真。
2. P-v1 与 Q-v1 的语义互引成环，而全部密码依赖保持 DAG。
3. 后发修订版不能偷换进早期系列包。
4. 合法平行分支不被误报为双重发布。
5. 相同排他论文槽位或系列序号的双签可被检出。
6. 新系列密钥必须由旧密钥授权。
7. 复制后重签不被误报成“已证明抄袭”。
8. 系列关系不被误报成自然人身份链接。
9. 签名完全正确但 `commitment_anchor_rank` 不高于所解析版本的系列包被拒绝。
10. 每条 `semantic_edges[].cites` 边必须两端属于包内工作，且至少有一份相应源论文版本的
    `reference_work_ids` 明确支持该边；该列表必须是精确正文中出现的规范 WorkID 令牌的去重投影，
    并且每次出现均有签名的 UTF-8 字节位置见证。系列签名者不能凭空捏造论文互引关系，也不能把复制正文里的旧 WorkID 重新标成新 WorkID，或把任意位置伪称为文本引用。
11. 签名正确但 JSON 非规范（包括多余空白、重复字段或非整数数值写法）的 release 被拒绝；签名字节不会被交给含糊的 JSON 解释规则。
12. profile 所引用的任一工件路径必须解析为项目根目录的后代；绝对路径、空路径和父目录逃逸均不得读取。
13. 规范 JSON 的接受/拒绝边界必须同时由 Python 参考实现与 Node.js 独立验证器在固定回归语料上逐例执行。
